When Cloudflare Zero Trust blocks a request, it shows a block page. This is a replacement
for the default one: a small SvelteKit app that explains what happened, shows the details
Cloudflare passed along, and gives the person a way to ask for access.

It is open source and built to be taken. Clone it, change a handful of strings, point it at
your own logo and support address, and it is your organisation's block page.

## What the page does

Cloudflare appends details about the block to the URL as query parameters. The page reads
them, shows the person a plain explanation, and puts the technical detail behind a
**details** panel rather than in their face.

From there they can:

- **Request access**, which opens their mail client with every detail of the block already
  written into the body, addressed to your support address.
- **Go to your support website**, from a button in the corner.

The point of the mail button is that it removes the worst part of being blocked. Instead of
someone describing "a website was blocked, I think, earlier", your support inbox gets the
rule ID, the site, the device and the timestamp, already filled in.

## It degrades sensibly

The page can be opened with no parameters at all, which happens if somebody visits the URL
directly or Cloudflare passes nothing along. It detects that and shows a shorter message
instead, with no empty details panel and no broken fields.

Individual missing values are handled the same way: a row only appears if it has something
in it, so you never get a screen of blank labels.
